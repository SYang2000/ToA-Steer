01

Tool use goes wrong in both directions

A tool call can fix a failed reasoning trajectory when computation or lookup is needed, but it can also add noise or overwrite an answer the model would have produced correctly on its own. The bottleneck for capable agents is not only tool competence but tool-use selectivity: deciding when to think and when to act.

ToA-Eval: when does a tool help this model?

For each problem and each model, ToA-Eval runs two controlled passes of the same base model — one without tools and one that must use a tool — and keeps only the cases where the tool changes the outcome. The same question can need a tool for one model but not another, so labels are derived separately for every model.

03

ToA-Steer: one direction, routed per query

A single static strength cannot serve both classes: ACT-needed inputs must move toward tool use and THINK-preferred inputs away from it. ToA-Steer keeps one shared direction and lets a lightweight router choose the sign and strength for each input.

1

Extract the direction

Two completions share the prompt and differ only in the decision: “Use [tools] to address this query.” vs. “Answer directly from your own knowledge.”

2

Route each query

The decision-token state is projected with PCA and assigned to the nearest K-means centroid; each cluster keeps the signed magnitude with the best held-out accuracy.

3

Steer every step

The same vector is added with the routed sign and strength: m>0 promotes a tool call, m<0 favours answering directly.

04

ToA-Steer reaches the highest accuracy and the best ACT and THINK tool-call rates in every model–benchmark cell, beating SFT and RL-trained GRPO without any parameter updates.

05

Inside the model

Five findings about where the THINK/ACT decision lives and why routing it per query pays off.

Finding 1 · Depth

The decision is written at a consistent depth

A logit lens at the prompt-end token shows the tool/skip preference staying near zero in early layers, rising across layers 20–28 and peaking at layer 26 on Qwen3-8B. All four models share a similar pattern.

Finding 2 · Structure

Decision regimes form clusters

Coloured by the steering magnitude that maximises accuracy, decision-token activations form coherent regions, so an unsupervised partition recovers useful routing groups — from K=2 on MATH to 5 on GPQA.

Finding 3 · Control

One direction is a clean control axis

Within a moderate range of |m| the tool-call rate rises smoothly with m, and accuracy peaks away from the no-steer baseline — but at a different m on each benchmark, so no fixed strength is optimal everywhere.

Finding 4 · Both directions

Gains on both classes, at moderate cost

ToA-Steer gains 16 points on ACT-needed and 9 points on THINK-preferred instances, improves both classes on every benchmark, and reaches the highest accuracy at a moderate tool-call rate.

Finding 5 · Headroom

Why route per query

Sweeping a single static magnitude traces a frontier that sits well below a per-sample oracle on every benchmark. This headroom is what per-cluster routing recovers.
